# Multiple wallets and HD addresses (0.5.0)

Use **Switch / add wallet** on Home or **Settings → Wallet & backup → Manage wallets**. Each created wallet has its own 12-word phrase and encrypted vault. Importing an already stored wallet is rejected after its identity is known. Wallet passwords and biometric enrollment are independent. Selection locks the current wallet; only the selected wallet's balance, transactions and reports are shown. Removing a wallet requires its authentication and removes only that wallet.

On first launch after upgrading, the existing encrypted vault is copied unchanged into Wallet 1. Its original receiving address and BIP84 account remain unchanged. A failed migration preserves existing data. Back up every wallet's own recovery phrase before deleting or reinstalling the app.

**Receive → Create new receiving address** derives the next unused receiving address. Previously shown addresses remain valid and their funds stay included in the balance. All discovered receiving (`m/84'/0'/0'/0/*`) and change (`m/84'/0'/0'/1/*`) addresses are combined. Outgoing transactions sign each input with its own derived key and return change to branch 1. Internal transfers count only network fees in cash-flow reports.

Discovery stops after 20 consecutive unused addresses per branch, while always scanning through the last address displayed locally. Settings offers gaps of 50 or 100 for restoring an account with larger unused gaps. Creating unused addresses beyond the selected gap is blocked. Discovery has a mobile safety limit of 2,000 addresses per branch: reaching it fails instead of presenting a partial balance. A seed alone cannot recover funds beyond an unknown unused gap without increasing the scan range in a compatible desktop wallet.

**Settings → Security → Authenticate & export zpub** requires the selected wallet's password or device authentication. Copy the account zpub or save a JSON file with only type, network, account path and zpub. It is public BIP84 account data, never an extended private key or seed. It permits watching receiving and change addresses and reveals account activity, so share it carefully. It does not replace a recovery-phrase backup. The dialog clears after 60 seconds, on lock, wallet switch or app backgrounding.

Notifications cover the selected wallet's known watch addresses. Background checks use that wallet's selected WSS endpoint and verify the BitcoinII genesis before sending address hashes; native TCP/TLS checks run in the foreground. Background summaries show the net change since the preceding check. Open the app to rediscover additional addresses used by another copy of the seed.

Validation: automated storage migration/isolation, public-key derivation, zpub round trip, both-branch discovery, multi-input signature verification and report reconciliation; Chromium mobile flows include creation, switching, independent passwords, new receiving addresses, public JSON export, persistence, send review and deletion isolation. Android builds and static native security checks pass. Hardware biometric prompts, document picker and background scheduling still require testing on a physical Android phone. This remains a debug-signed testing release without an independent security audit.
